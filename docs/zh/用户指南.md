# 1 a2a-t-sdk-python 用户指南

> SDK 版本：1.1.0 —— 本版本对应 Java a2a-t-sdk 1.1.0 能力面。

## 1.1 特性介绍
### 1.1.1 什么是A2A-T？
A2A-T（Agent-to-Agent Telecom）是基于A2A协议推出的电信领域多智能体互联协议，专为电信领域复杂协同场景设计。
业界通用智能体互联协议主要关注智能体互联和交互框架，对业务场景和具体交互内容关注不足，导致任务完成的成功率不高。电信领域的业务场景复杂、要求高，运维智能体互联和协同需要有专门的协议进行支撑。A2A-T方案基于A2A协议，重点针对电信领域业务流相关的信息模型、任务协商、协作安全等增强能力进行应用扩展。

### 1.1.2 A2A-T SDK与A2A SDK的关系

A2A-T协议是基于A2A协议的扩展，针对协议扩展的内容提供了A2A-T SDK，支撑快速构建满用于电信领域复杂协同场景的智能体。A2A-T SDK独立于A2A SDK，通过同时集成A2A-T SDK与A2A SDK可以构建支持A2A-T协议的agent，支持电信领域多agent之间的确定性、高可靠、高效及安全协同。

### 1.1.3 能力介绍

a2a-t-sdk-python是面向电信智能体协作场景的 Python SDK，用于在 A2A-T 交互中生成、校验和协商任务提示词。SDK 适合客户端 Agent、服务端 Agent 以及上层编排系统集成使用。

主要能力包括：

- **任务提示词生成**：客户端从自然语言生成 processed task prompt（场景识别流程），或通过 `from_text` / `from_data_with_schema` 入口显式指定模板，从文本或结构化输入生成 Task-T、Notification-T、Authorization-T 提示词。
- **服务端提示词校验与参数填充**：服务端校验 processed task prompt 是否匹配模板与槽位约束（`check_task_prompt`），并可按调用方提供的参数 schema 校验提示词并提取参数（`validate_{task,notification,auth}_prompt_and_data_filling`）。
- **协商内容 API**：Negotiation-T 扩展上的 12 个方法 —— `generate_{propose,accept,reject,abort}_prompt_from_{data,text}` 生成协商消息，`validate_{propose,accept,reject,abort}_prompt_and_data_filling` 校验协商消息。会话状态随报文在 A2A-T metadata（`negotiationContext`）中往返，SDK 本身无状态。
- **模板查询**：`get_prompts` / `get_prompt` 列出并加载当前语言下所有扩展可用的模板。
- **提示词资源管理**：内置场景、槽位、模板、词表和系统提示词资源，双语（zh-CN / en-US）成对提供；业务内容支持从本地目录覆盖。
- **LLM 适配**：通过 OpenAI-compatible 调用链接入外部大模型，对可重试失败码提供有界重试。
- **结构化双语错误模型**：封闭的 42 个机器可读错误码目录（含事实参数），按配置语言渲染消息，结果类 API 携带结构化 failure 数据类。

## 1.2 应用场景

Python SDK 通常用于以下场景：

1. 客户端 Agent 接收用户意图，生成结构化任务提示词后通过 A2A 协议发送给目标 Agent。
2. 服务端 Agent 接收任务提示词，执行合规、模板和槽位校验，按需提取业务参数，再进入业务处理。
3. 当任务信息不足、任务目标不清晰或能力可行性需要确认时，双方通过协商内容 API 生成与校验 Negotiation-T 消息（propose / accept / reject / abort）推进交互，协商上下文随每条消息的 A2A-T metadata 往返。

## 1.4 安装

### 1.4.1 安装 SDK

源码方式（开发）：

```bash
cd {项目路径}/a2a-t-sdk-python
uv sync --dev
```

PyPI 方式（集成）：

```bash
pip install a2a-t-sdk
```

执行测试套件确认环境可用（套件默认离线确定性；live-LLM 测试在环境变量缺席时自动 skip）：

```bash
uv run pytest -q
```

### 1.4.2 准备 SDK 配置

SDK 从 `.env` 文件读取配置（不读取操作系统环境变量）。复制模板并编辑：

```bash
cd {项目路径}/a2a-t-sdk-python
cp env.example package_data/.env
```

`package_data/.env` 是 `A2ATClient` / `A2ATServer` 的默认读取位置；两个门面也接受显式的 `env_path` 参数。仓库根目录的 `env.example` 携带完整的带注释键清单。

至少需要配置 LLM 接入信息：

```properties
A2AT_LANGUAGE=zh-CN
A2AT_PROMPT_SOURCE_TYPE=packaged
A2AT_LLM_PROVIDER=openai
A2AT_LLM_MODEL=deepseek-chat
A2AT_LLM_API_KEY={your_api_key}
A2AT_LLM_BASE_URL=https://api.deepseek.com
```

> SDK 通过 OpenAI-compatible 接入外部大模型，`A2AT_LLM_PROVIDER` 当前仅支持 `openai`；接入 DeepSeek 等 OpenAI 兼容服务时，通过 `A2AT_LLM_BASE_URL` 指定服务地址、`A2AT_LLM_MODEL` 指定模型名。

> 自 1.1.0 起，提示词资源默认来源为 `packaged`：提示词、模板、词表均从已安装的包内读取，SDK 无需任何资源配置即可开箱即用。如需保留从目录读取资源的行为（1.1.0 之前的默认），设置 `A2AT_PROMPT_SOURCE_TYPE=local_file` 并将 `A2AT_PROMPT_RESOURCE_LOCAL_ROOT_DIR` 指向你的资源根目录，见 1.6.1。

## 1.5 快速开始

以下代码片段使用 `env_path=Path("package_data/.env")`；省略该参数即使用默认位置。

### 1.5.1 客户端生成任务提示词

从自然语言生成 processed task prompt。场景识别入口自动选择场景与模板：

```python
from pathlib import Path

from a2a_t.client.a2at_client import A2ATClient

client = A2ATClient(env_path=Path("package_data/.env"))
result = client.generate_task_prompt(
    "请生成一个Incident事件订阅任务：通知主题为Incident，订阅级别为critical、medium、high、low，"
    "上报通知数据格式为DataPart"
)

if result.success:
    print(result.prompt_text)
else:
    # 结构化失败信息：code / message / stage（见 1.7）
    print(result.failure.code, result.failure.message)
```

目标模板已知时，可跳过场景识别，用模板 URI 显式寻址（一次 LLM 槽位抽取，随后确定性渲染）：

```python
metadata = client.generate_notification_prompt_from_text(
    "订阅业务恢复事件；上报恢复计划执行状态与投诉诊断任务流水号",
    "Notification-T/network-layer/subscribe-incident/v1",
)
print(metadata.prompt_text)                # 渲染出的提示词文本
print(metadata.template_uri)               # "Notification-T/network-layer/subscribe-incident/v1"
print(metadata.extension_uri)              # Notification-T 扩展 URI，用于 A2A metadata
print(metadata.build_metadata_content())   # 可直接使用的 A2A-T metadata 映射
```

结构化输入通过 `*_from_data_with_schema` 入口以相同方式工作：传入输入字段以及描述各字段含义的 schema：

```python
metadata = client.generate_task_prompt_from_data_with_schema(
    {"site": "松山湖园区", "target": "能耗降低30%"},
    {"site": "任务作用的目标站点", "target": "优化目标"},
    "Task-T/network-layer/ran-energy-saving/v1",
)
```

六个显式寻址入口分别是 `generate_{task,auth,notification}_prompt_from_text` 与 `generate_{task,auth,notification}_prompt_from_data_with_schema`。建议使用 `a2a_t.core.standard_templates` 的常量（如 `ENERGY_SAVING_URI`、`SUBSCRIBE_INCIDENT_URI`、`AUTHORIZATION_POLICY_MANAGEMENT_URI`），避免手写 URI 字符串。

### 1.5.2 服务端校验提示词

`check_task_prompt` 校验 processed prompt 是否匹配场景、模板和槽位约束，返回结果对象而不抛异常：

```python
from pathlib import Path

from a2a_t.server.a2at_server import A2ATServer

server = A2ATServer(env_path=Path("package_data/.env"))
result = server.check_task_prompt(processed_prompt_text=prompt_text)

if result.success:
    print("prompt check passed")
else:
    print(result.failure.code, result.failure.stage, result.failure.message)
```

服务端需要提示词携带的业务参数时，使用参数填充校验器：按寻址模板校验提示词，并按调用方提供的 JSON schema 提取参数：

```python
from a2a_t.core.errors.exceptions import ContentValidationError

schema = {
    "type": "object",
    "properties": {
        "topic": {"type": "string", "description": "要订阅的事件主题"},
        "notificationDataFormat": {"type": "string", "description": "上报的数据格式"},
    },
    "required": ["topic", "notificationDataFormat"],
}

try:
    filled = server.validate_notification_prompt_and_data_filling(
        metadata.prompt_text, schema, "Notification-T/network-layer/subscribe-incident/v1"
    )
    print(filled.data)  # 提取出的参数，如 {"topic": "Incident", ...}
except ContentValidationError as exc:
    print(exc.code_str, exc.facts)  # 目录错误码与结构化事实值
```

`validate_task_prompt_and_data_filling` 与 `validate_auth_prompt_and_data_filling` 分别是 Task-T 与 Authorization-T 扩展的对应入口。

### 1.5.3 一次协商往返

一次协商交互是一对 Negotiation-T 消息：一方生成 propose 消息说明所需内容，另一方校验该消息并以 accept（或 reject）消息应答。下面的往返完全离线 —— from-data 生成路径不调用任何 LLM。

```python
import uuid
from pathlib import Path

from a2a_t.client.a2at_client import A2ATClient
from a2a_t.core.metadata import NegotiationContext, NegotiationPerformative
from a2a_t.negotiation.content.enums import NegotiationConclusion
from a2a_t.negotiation.content.models import (
    InformationEndingContent,
    InformationProposeContent,
    NegotiationEndingData,
    NegotiationItem,
    NegotiationProposeData,
)
from a2a_t.server.a2at_server import A2ATServer

PROPOSE_URI = "Negotiation-T/information-negotiation/propose/v1"
ACCEPT_REJECT_URI = "Negotiation-T/information-negotiation/accept-reject/v1"

client = A2ATClient(env_path=Path("package_data/.env"))
server = A2ATServer(env_path=Path("package_data/.env"))

# 1) 服务端就缺失信息发起询问：由类型化内容构建的 propose 消息
#    （确定性生成，零 LLM 调用）。会话上下文的 id 必须是 UUID。
context = NegotiationContext.of(str(uuid.uuid4()), 1, NegotiationPerformative.PROPOSE)
propose = server.generate_negotiation_propose_prompt_from_data(
    NegotiationProposeData(
        context=context,
        content=InformationProposeContent(
            items=[NegotiationItem(name="faultLevel", value="需要订阅的故障级别")],
            relationship=None,
        ),
    ),
    PROPOSE_URI,
)
print(propose.prompt_text)
print(propose.build_metadata_content())  # 携带 negotiationContext：id/round/maxRounds/performative

# 2) 客户端校验收到的消息并提取所请求的参数
filled = client.validate_propose_prompt_and_data_filling(
    propose.prompt_text,
    propose.negotiation_context,
    {"type": "object", "properties": {"faultLevel": {"type": "string"}}, "required": ["faultLevel"]},
    PROPOSE_URI,
)

# 3) 客户端以携带补充信息的 accept 消息应答
accept = client.generate_negotiation_accept_prompt_from_data(
    NegotiationEndingData(
        context=propose.negotiation_context.next_round().with_performative(NegotiationPerformative.ACCEPT),
        content=InformationEndingContent(
            conclusion=NegotiationConclusion.ACCEPT,
            items=[NegotiationItem(name="faultLevel", value=str(filled.data["faultLevel"]))],
        ),
    ),
    ACCEPT_REJECT_URI,
)
print(accept.prompt_text)
```

同一交互也可以用 `*_from_text` 变体（`generate_negotiation_propose_prompt_from_text` 等）从自然语言驱动：先执行一次 LLM 内容抽取，再进行与 from-data 相同的确定性渲染。

完整的四消息闭环（缺失参数的 Task-T 提示词 → Negotiation-T propose → 补齐参数的 Task-T 提示词 + accept → 结果）可运行离线样例查看；样例无需 LLM API Key，LLM 步骤由脚本化 mock LLM 承担：

```bash
cd {项目路径}/a2a-t-sdk-python/a2a-t-sample
cp env.example .env
uv pip install -r requirements.txt
uv run python -m negotiation_demo                 # from-data 策略（零 LLM 调用）
uv run python -m negotiation_demo --fromText      # from-text 策略（mock LLM）
uv run python -m negotiation_demo --language zh-CN
```

### 1.6.1 迁移：1.1.0 资源来源默认值变更

1.1.0 之前 `A2AT_PROMPT_SOURCE_TYPE` 的默认值是 `local_file`；1.1.0 起改为 `packaged`，与 Java SDK 的 `classpath` 默认对齐。开箱即用时 SDK 从已安装包内读取资源，本地路径配置错误会显式报错，而不是静默读到意外文件。

如需恢复 1.1.0 之前的行为，设置：

```properties
A2AT_PROMPT_SOURCE_TYPE=local_file
A2AT_PROMPT_RESOURCE_LOCAL_ROOT_DIR=/path/to/your/prompt_resources
```

只有业务内容（`templates/`、`slots/`、`scenarios/`、`negotiation-vocabulary/`）从本地根目录读取；LLM 指令提示词（`prompts/`）与错误消息模板（`errors/`）始终从已安装包内加载。整个本地根目录在门面构造时被冻结为一次快照，文件修改需重启进程后生效。

## 1.7 错误处理

SDK 采用双轨错误模型：

- **返回结果的入口**（`generate_task_prompt`、`check_task_prompt`）不抛业务失败：失败信息以结构化冻结数据类的形式随结果对象返回。
- **抛异常的入口**（六个 `*_from_text` / `*_from_data_with_schema` 方法、十二个协商方法以及 `validate_*` 校验器）抛出携带机器可读目录错误码的类型化异常。

### 1.7.1 Failure 数据类

`PromptGenerationResult.failure` 是 `PromptGenerationFailure`，`PromptComplianceResult.failure` 是 `PromptComplianceFailure`；两者携带相同的三个字段：

| 字段      | 说明                                                |
|-----------|-----------------------------------------------------|
| `code`    | 机器可读的目录错误码字符串，如 `slot.not_provided`   |
| `message` | 按错误码双语模板渲染的可读消息                       |
| `stage`   | 失败发生的流水线阶段                                 |

两个数据类都提供 `to_dict()`，可直接 JSON 序列化。

### 1.7.2 错误码目录与异常树

每个业务失败都携带封闭目录 42 个分层 `domain.semantic` 码（`template.not_found`、`slot.rule_violation`、`content.param_missing`、`negotiation.conclusion_mismatch`、`llm.invocation_failed`、`input.text_too_long`、`infra.config_invalid` 等）之一，每个码带类别（business / infra）与声明的事实参数。所有异常派生自单一根 `A2ATError`；业务失败派生自携带错误码与结构化事实值的 `A2ATBusinessError`：

```python
from a2a_t.core.errors.exceptions import A2ATBusinessError, NegotiationGenerationError

try:
    metadata = client.generate_negotiation_propose_prompt_from_data(data, PROPOSE_URI)
except NegotiationGenerationError as exc:
    print(exc.code_str)   # "negotiation.content_invalid"（纯字符串，可直接进 JSON）
    print(exc.facts)      # {"field": "...", "reason": "..."}（结构化事实值）
    print(exc.message)    # 按配置语言渲染的消息
except A2ATBusinessError as exc:
    print(exc.code_str, exc.facts)  # 其他任何业务失败
```

模块级异常类型包括 `PromptGenerationError`、`ContentValidationError`、`A2ATParamExtractionError`、`NegotiationGenerationError` 与 `NegotiationParamExtractionError`；捕获 `A2ATBusinessError` 即覆盖全部。编程错误（`None`、空白或畸形参数 —— 包括畸形模板 URI）刻意保留在异常树之外，以 `TypeError` / `ValueError` 抛出。可重试的 LLM 失败码（`llm.invocation_failed`、`llm.response_invalid`、`negotiation.content_extract_failed`）在 SDK 内部按 `A2AT_LLM_MAX_ATTEMPTS` 有界重试；重试耗尽后重抛原始错误码。

### 1.7.3 双语错误消息

错误消息由包内 `prompt_resources/errors/{language}/errors.json` 模板按 `A2AT_LANGUAGE` 渲染，事实值替换进 `{name}` 占位符。渲染过程 never-throw：请求语言缺模板时回落 `en-US`，两种语言都缺时渲染为裸错误码，目录不可读仅记录告警。

## 1.8 双语支持

SDK 的全部用户可见资源均同时提供 `zh-CN` 与 `en-US` 两个语言版本：

- 提示词模板（`templates/<extension>/<path>/v1/{zh-CN,en-US}/template.md`）；
- 槽位 schema、场景目录与协商词表；
- LLM 指令提示词；
- 42 条错误消息模板。

设置 `A2AT_LANGUAGE` 即可整体切换运行时语言。协商词表在两种语言之间做严格 parity 校验，协商模板与 Java 侧保持字节一致，因此两种语言暴露相同的能力面。

## 1.9 约束与限制

1. SDK 无状态：协商会话状态随每条消息的 A2A-T metadata（`negotiationContext`）往返，不保存在 SDK 内部。
2. 旧的状态机协商 demo（`start_negotiation` / `receive_negotiation` / `continue_negotiation` 及其 `in_memory` 状态存储）自 1.1.0 起废弃，将在下一版本删除；请改用协商内容 API（见 1.5.3）。
3. 提示词资源支持两种来源（`packaged` 与 `local_file`）；不支持从注册中心远程加载资源。
4. 自由文本输入有长度上限（`A2AT_INPUT_TEXT_MAX_CHARS`，默认 16384），超限快速失败而非截断；结构化 `from_data` 输入不受该限制。
5. SDK 负责 A2A-T 提示词生成、校验和协商，不负责 AgentCard 注册、鉴权、服务托管和业务执行。
